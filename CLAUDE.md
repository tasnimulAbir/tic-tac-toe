## Overview

Two-player local Tic Tac Toe with a stats dashboard, in plain HTML, CSS, and JavaScript. No build step, package manager, dependencies, linter, or tests.

## Running

Open `index.html` directly in a browser (`open index.html` on macOS). For a local server: `python3 -m http.server` and visit http://localhost:8000.

## Architecture

- `index.html` holds the static markup: a game panel (player chips, status, board, New Round) and a dashboard panel (KPI tiles, results split bar, streak and average-moves cards, winning-squares heatmap, recent games). The 9 board cells are `<button class="cell" data-index="0..8">` elements written out by hand, not generated by JS. `script.js` relies on `data-index` matching each cell's position in `querySelectorAll(".cell")`.
- `script.js` keeps game state in module-level variables: `board` (an array of 9 entries, each `"X"`, `"O"`, or `null`), `currentPlayer`, `gameOver`, `moveCount`, and `history`.
  - `WIN_LINES` lists the 8 winning index triples.
  - `handleCellClick` places a mark, then checks for a win or a draw, or switches turns (and the active player chip via `setActivePlayer`).
  - `endGame` appends `{ result, moves, line, board, at }` to `history`, saves it, re-renders the dashboard, and marks all cells `aria-disabled`. `board` is stored as a 9-char string (`"X"`, `"O"`, `"-"`).
  - `startRound` clears the board but keeps history.
  - `resetScores` (the "Clear stats" button) confirms, then empties `history`, leaving the current round in play.
  - History persists in `localStorage` under `ttt-history`; the theme choice under `ttt-theme`. Every storage access is wrapped in try/catch so the game still works when storage is blocked.
- Dashboard: every number is derived from `history` by `computeStats` (counts, heatmap, average moves, current and best streak); `renderDashboard` calls one `render*` function per widget. Scores are not stored separately.
- Tooltips: any element with `data-tip` shows the shared `#tooltip` on hover.
- Accessibility: played cells and cells in a finished game get `aria-disabled="true"` rather than `disabled`, so they stay focusable. `handleCellClick` ignores clicks on them. Each cell's `aria-label` ("Row 1, column 1, X") is set by `cellLabel` after every move and in `startRound`. `#status` is a live region (`role="status"`). The split bar and heatmap squares carry `aria-label`s; KPI identity is a colored dot plus a text label, never color alone.
- CSS classes set by JS:
  - `.x` / `.o` color each mark.
  - `.win` highlights the winning line.
  - `.active` marks the player whose turn it is.
  - `startRound` resets each cell with `cell.className = "cell"`, so any new per-cell class must be re-added there.
- Theming: `style.css` keeps colors in custom properties on `:root` (`--x`, `--o`, `--win`, `--seq`, etc.), with a dark set under `prefers-color-scheme: dark` and again under `:root[data-theme="dark"]` (the toggle button sets `data-theme`). Change a dark color in both places. `--x`/`--o` were checked as a colorblind-safe pair for each theme's surface; re-check if you change them.
